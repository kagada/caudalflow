## 2. 工作区与个人数据分开保存（已实现）

一个工作区对应一个 SQLite 文件，扩展名为 `.caudalflow`。用户可以选择位置、打开、搬运和分享文件。

| 数据 | 保存位置 |
|---|---|
| 会话、问题、回复、文档版本、会话关系和布局 | 工作区 SQLite 文件 |
| 图片等资产 | 工作区数据库的 BLOB，通过版本与资产的关联记录组织 |
| 个人本地历史 | 应用用户目录中的独立 SQLite 文件，不随工作区文件搬运 |
| 设置、密钥、最近工作区目录 | 应用用户目录；密钥不进入工作区文件 |

桌面版使用 Electron 自带的 `node:sqlite`，数据库操作在独立工作线程执行，上层通过异步存储接口访问。工作区与独立历史使用 `ATTACH` 和回滚日志事务协调写入，不使用 WAL。

原 localStorage 工作区的迁移已经实现：迁移前保留原始 JSON 备份，保留原 localStorage 数据，失败时不以空工作区覆盖原内容。

## 3. 当前数据组织（已实现）

- 运行时由 store 提供当前界面数据，持久化与内容回放通过统一存储模块协调。
- 一个问题或回复是一份文档，有稳定文档 ID 和时间；不同内容保存为不可变版本，各版本有自己的 ID。
- 会话组织文档顺序及当前选用版本。切换版本不需要更换文档 ID。
- 图片独立保存，通过文档版本关联；布局与会话内容分开。
- 流式回复使用草稿检查点，不为每个 token 建立版本或历史记录。

现有表包括工作区信息、会话、布局、文档、文档版本、会话文档组织、资产、版本资产关联、会话关系和生成草稿；不再将表结构、版本组织或资产内置方式列为未定事项。后续引用功能可以按需要扩展这些结构。

## 4. 撤销重做与本地历史（已实现）

撤销重做按工作区、按本次运行维护，重启后清空。覆盖会话、问题、回复和会话名称、标签、搞定状态等内容修改；拖动、缩放、尺寸与折叠不进入内容操作栈。重做使用保存的结果，不重新请求 AI。

创建空会话、首次提问、自动标题和首次回复作为初始化：没有其他内容操作插入就持续合并为一条历史和一个撤销步骤，标题与回复的完成顺序不限。其他内容操作或撤销会结束合并；布局变化不打断合并。

本地历史独立于 Git，也独立于工作区分享。界面按“修改记录 → 涉及的会话与内容 → 操作前后差异”呈现，先比较 Markdown 原文；问题、图片及对应回复按一组查看，不做渲染后 Markdown 对比。

可以还原选中内容、整个会话或整个工作区。还原本地历史不可撤销，并清空撤销重做队列。删除工作区不可撤销，也不通过本地历史恢复。

当前个人历史默认保留 30 天、最多 200 次操作、约 64 MiB 的记录内容；文档功能版本当前最多保留 50 个。引用功能所需的快照必须另行保留，不能依赖这些会被清理的记录。
